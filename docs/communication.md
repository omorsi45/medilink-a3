# Communication

## Async by default
Daily updates go in issue #10 as comments, in this format:

```
Completed: what moved forward, with issue/PR numbers
Planned: what's next, with issue numbers
Blockers / help needed: what's stuck and what would unblock it (or "none")
```

The rule is that every line points at an issue or PR. If a line can't point at one, either the work isn't tracked (make an issue) or it isn't worth reporting.

Stays async:
- Daily progress (issue #10)
- Questions about one item (comment on that issue)
- Review comments (on the PR)
- Small decisions that are easy to undo (comment, then go ahead)

## When to switch to a call
1. A production incident that affects patients right now (like #1). Async is too slow when wrong reminders are going out.
2. A blocker that's sat for more than one checkpoint with no answer in the comments.
3. A review thread that goes back and forth more than twice on the same point.
4. A decision that changes the release scope or the plan for everyone.

Working alone I don't have anyone to call. In this cycle, hitting one of these meant stopping my other work and dealing with it right away. Once I'm in Group 14 for A4, these are the points where I'd ask for a short call.
